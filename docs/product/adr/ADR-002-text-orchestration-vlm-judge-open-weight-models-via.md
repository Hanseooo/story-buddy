# ADR-002 — Text/orchestration + VLM judge: open-weight models via OpenRouter

**Status:** Accepted · **revised 2026-07-10** — supersedes the original Gemini decision. Driver: ADR-015.
· **amended 2026-08-11** — the text model changes, and the reason generalises: on OpenRouter the
*provider*, not the model, decides structured-output fidelity. The aggregator decision stands.
· **amended 2026-08-12** — Instance 4: the replacement model failed the same property on a
different provider. Pinning is now paired with a re-ask, because no allowlist is a complete
measurement. The aggregator decision still stands.

**Context:** Story analysis, segmentation, prompt-building, and the VLM-judge need a capable LLM/VLM with **reliable structured output**. The open-weight mandate (ADR-015) rules out Gemini. Serving open weights ourselves is rejected in ADR-015; we need an aggregator that fronts many open models behind one OpenAI-compatible API so a model swap is a config change.

**Decision:** Use **OpenRouter**. Text pipeline nodes: ~~**`qwen/qwen3-32b`**~~ → **`mistralai/mistral-small-3.2-24b-instruct`** (amended 2026-08-11; the struck model is kept because it passed Probe 3 and that result is real — see the amendment). VLM judge: **`google/gemma-3-27b-it`**. Fallbacks, pre-vetted for structured-output support: `openai/gpt-oss-20b` (text, Apache-2.0) and `qwen/qwen3-vl-32b-instruct` (judge).

**Amendment (2026-08-11) — a probe result is valid for the `(model, provider)` pair that served it, and for nothing else.**

This ADR's own Consequences already said structured-output support is per `(model, provider)`, not per model, and prescribed `provider.require_parameters: true` as the mitigation. **The mitigation is weaker than the sentence implies, and two production failures on the same day proved it from opposite ends of the pipeline.** `require_parameters: true` selects providers that **accept** `response_format` — it does not select providers that **honour** it. Acceptance is a capability flag on a routing table; fidelity is a property of how that provider decodes.

**Instance 1 — `text_model`, prod job `af068baf`.** OpenRouter routed `qwen/qwen3-32b` to **DeepInfra**, which spent **1093 of 1497** completion tokens on a reasoning block and then returned JSON that violated the strict schema (nested objects where `str` was declared). Root cause: **grammar-constrained decoding cannot be applied across a thinking block** — the constraint resumes after the model has already committed to a shape. Nothing was misconfigured; `require_parameters` was sent, as `providers._chat` sends it on every OpenRouter call. **Probe 3 passed this exact model on 2026-07-29** (`PHASE_05_RESULTS.md`), on whichever provider the router happened to pick that day.

**Instance 2 — `moderation_primary_image_model`.** `qwen/qwen3-vl-32b-instruct`, served by **Alibaba Cloud**, emitted `is_safe` **before** `safety_reasoning`. `providers._assert_field_order` (`backend/providers.py:74`) rejects that under ADR-004's reason-then-score rule and raises, **hard-failing the job at `char_ref_mod`** — the child-facing safety gate, i.e. the worst node to learn this in. Schema-order violation is a *different* symptom from Instance 1's schema violation, but it is the same cause: the provider produced tokens the declared grammar should have made unproducible.

**Both were fixed by the same move:** `mistralai/mistral-small-3.2-24b-instruct` on both settings (`backend/app/config.py:32` and `:60`). It is not a reasoning model, it is multimodal, and it returned schema-compliant, correctly-ordered structured output first try in the same run that the two above failed. The image guard stays a **different family** from the Gemma backstop, so ADR-011's two-classifier diversity survives the swap.

**Instance 3 (added later the same day) — `require_parameters` does not cover *modality* either, and here there is no model choice that fixes it.** Prod job `f4d0fd74` died at `output_mod` on scene s5: OpenRouter returned **400 — "Image content is not supported by this model. Please use a model that supports vision."** from **Venice**. `mistralai/mistral-small-3.2-24b-instruct` is genuinely multimodal (`input_modalities: ["image", "text"]`), but it is served by exactly three providers — DeepInfra, Parasail, Venice — and Venice's `venice/fp8` deployment is text-only. DeepInfra and Parasail had both 429'd on the shared pool, so the router fell through to the one endpoint that could not do the job. `require_parameters` selects on the top-level request **parameters**; images live in `messages` content, so Venice passed the filter and then rejected the payload.

**The mitigation is a per-model provider allowlist, because OpenRouter offers nothing better.** Verified 2026-08-11 against `https://openrouter.ai/docs/features/provider-routing`: the `provider` object has `order`, `only`, `ignore`, `allow_fallbacks`, `require_parameters`, `quantizations`, `sort`, `max_price`, `data_collection`, `zdr` — and **no input-modality filter**. `GET /models/{id}/endpoints` does not report per-endpoint modalities either, so this is not discoverable at runtime. `providers.VISION_PROVIDERS` pins the affected model to `["deepinfra", "parasail"]`, read **only** by `judge` — the one function that sends images. Three properties are deliberate:
- **Allowlist, not an `ignore: ["venice"]` blocklist.** This is the safety path; a provider added later should be excluded until someone confirms it serves images.
- **Per model, not global.** `gemma-3-27b-it` (image backstop *and* consistency judge) has five providers, none of them Venice — pinning it would shrink its pool for nothing.
- **Per call site, not per model ID.** The same model is `text_model`, where Venice is a perfectly good route. ~~The pin belongs to the call that carries an image.~~ **Amended 2026-08-12 — the principle held and the conclusion did not.** Both call sites now pin this model, to *different* lists: `VISION_PROVIDERS = ["deepinfra", "parasail"]`, `TEXT_PROVIDERS = ["deepinfra", "venice"]`. Parasail can serve an image and cannot honour a strict schema; Venice is the exact reverse. Until Instance 4 the two lists were only hypothetically different, which is why the rule read as bookkeeping — it is now the thing keeping two incompatible constraints off each other.

**A 400 is not a 429.** The SDK does not retry it, so `MAX_RETRIES` (restored hours earlier, in the ADR-025 amendment) cannot cover this class at all. Pinning removes the cause; the `output_mod` posture fix shipped alongside it removes the *consequence*, so a future unroutable vision call degrades to backstop-only instead of killing a fully-paid book.

**Instance 4 (2026-08-12) — the first one the model choice does not explain, and the reason pinning alone was never going to be the answer.** Prod row `558afb6d` died in `analyze`. `mistralai/mistral-small-3.2-24b-instruct` — the model this ADR swapped *to*, precisely because it is not a reasoning model — returned a **200 in 363ms** carrying `{'species': 'location', …}` in four fields declared `str | None`. Those are `locations[0..2].description` and `objects[0].description`; `species` appears nowhere in `StoryAnalysis` except `ExtractedDescription`, the *character* sub-schema. The model copied one sibling's shape into the others', which grammar-constrained decoding makes unproducible — so that answer was never constrained. `TEXT_MODEL` was the intended default and `require_parameters` was sent. OpenRouter's activity log names the route: **Parasail** (`gen-1786523891-ZW5XHaXPUfbTXdd0cIF3`).

**Two mitigations, because neither is sufficient alone — this is the transferable part.**

- **`providers.TEXT_PROVIDERS`** pins `structured_text` to `["deepinfra", "venice"]`. This deterministically removes the observed cause, and nothing more. Every allowlist in that module is an *incomplete measurement*: no one has established that the providers left on a list decode more faithfully than the one taken off, only that the one taken off failed. Instance 1 was fixed by changing the model, Instance 3 by pinning, and this instance says the fix that worked twice is a fix for one route at a time.
- **One re-ask in `providers._chat`.** Every way a provider can break its own grammar surfaces as a `ValueError` — pydantic's `ValidationError` subclasses it, as do the `parsed is None` and `_assert_field_order` raises — so one `except` covers Instances 1, 2 and 4 together. **`MAX_RETRIES` cannot and never could**: it is the SDK's transport retry keyed on HTTP status, and a provider that ignores the schema answers 200. Before this, a single malformed completion killed a fully-paid book with no tolerance anywhere in the pipeline; `grep -rn ValidationError backend --include=*.py` returned tests only.

**Why both, stated plainly:** the pin cannot protect the judge, which keeps Parasail allowlisted *because* it can serve an image, and the judge is the one call site where a grammar violation lands on the child-facing safety gate (Instance 2). The re-ask cannot be the whole answer either — OpenRouter may route the retry straight back to the same provider, so it is probabilistic where the pin is deterministic. **One re-ask, not a loop:** a provider that cannot honour the schema will not learn to on the fourth attempt, and every attempt is billed. A `TimeoutError` from `_bounded` is deliberately *not* retried (it is an `OSError`, not a `ValueError`), so the worst case against the 900s job deadline stays one `CALL_TIMEOUT_SECONDS`, not two.

⚠️ **`_assert_field_order` is not softened.** It still raises, as the consequence below requires; the re-ask happens *before* that raise reaches the pipeline, and a second violation still fails the job. Asserted in `test_two_violations_in_a_row_still_fail_the_job`.

**Operational consequences — state these plainly, they are the transferable part:**
- **`require_parameters` is a floor on three separate axes now, and clears none of them.** It does not guarantee a provider *honours* `response_format` (Instance 1), *orders* its fields (Instance 2), or *accepts the modality* the model advertises (Instance 3). Treat a model's advertised `input_modalities` as a property of the **model**, never of the endpoint that will serve it.
- ~~**The guard is the model choice, not the flag.**~~ **Amended 2026-08-12 by Instance 4 — the model choice is a guard, and not a sufficient one.** Both halves of that sentence survive: `require_parameters: true` stays on (it still prevents the silent `json_schema` → `json_object` downgrade this ADR was originally written about) but is a floor, not a contract; and **do not adopt a reasoning/thinking model for a strict-schema call**, nor assume a multimodal model orders fields the way the schema declares them. What Instance 4 removes is the implied *sufficiency*. The model that sentence was written to recommend went on to fail the same property on a different route. **The only guard that does not depend on getting a routing question right in advance is tolerating the bad answer** — hence the re-ask in `_chat`.
- **A probe result carries its provider with it.** "Probe 3 PASS" means *that model, on the provider OpenRouter routed to on 2026-07-29*. OpenRouter re-routes silently. A passing probe therefore **does not predict production** and never did — the probe measures reachability of a call shape, not a durable property of a model ID. `PHASE_05_RESULTS.md` and `MASTER_SPEC.md` §8 carry a dated note saying so; the original results stand unedited.
- **`_assert_field_order` earned its keep.** It converted a silent voiding of ADR-004's mitigation into a loud job failure, which is why Instance 2 was diagnosed in minutes rather than shipped. Do not soften it into a warning.
- **The deterministic suite cannot catch this class** — every test mocks `providers.py`. `backend/tests/test_smoke_providers.py` (2026-08-11) is the check; run `uv run pytest -m "smoke and not smoke_image"` before any deploy that changes a model ID, a base URL, or a provider (AGENTS.md, *Testing bright line*).
- **ADR-015 is satisfied, checked rather than assumed.** `mistralai/mistral-small-3.2-24b-instruct` ships **Apache-2.0** open weights, hosted-inference-only by choice — the same posture ADR-015 already rules compliant, and a cleaner licence than the Gemma-licensed judge this ADR also names. The open-weight mandate is unaffected; no ADR-015 amendment is needed.
- ADR-011 §3 and ADR-032 still name `qwen/qwen3-vl-32b-instruct` as the primary image guard. **This amendment supersedes that model choice** on the ground above; ADR-011's *design* — two classifiers, different vendors, either flag fails — is untouched and is the reason the swap was safe to make.

**Consequences:**
- ⚠️ **OpenRouter's structured-output support is per `(model, provider)` pair, not per model.** A routed provider that lacks it silently downgrades `json_schema` to loose `json_object` mode. **Always send `provider.require_parameters: true`**, and re-query `GET /api/v1/models?supported_parameters=structured_outputs` before implementing — the list changes. Without this, the Pydantic boundary (CLAUDE.md §2) is the *only* thing standing between a malformed response and the pipeline.
- OpenRouter is OpenAI-compatible, so LangSmith tracing (ADR-014) works unchanged.
- Swapping a model is an env-var change; swapping the *provider* is one file (`backend/providers.py`).
- **The child's text still leaves our infrastructure** (OpenRouter → upstream host). PII redaction (ADR-011) remains load-bearing. This ADR does **not** deliver a privacy guarantee — see ADR-015.
- ~~Read-aloud captions use the browser's Web Speech API.~~ **Superseded by ADR-020** — expressive
  open-weight TTS (**Chatterbox**, MIT) via **hosted inference on fal.ai**, pre-rendered per page; Kokoro-82M
  retained as the CPU fallback. Same hosted-open-weights mechanism as this ADR; no proprietary dependency.
- The **judge's endpoint** is no longer necessarily OpenRouter. After Phase 2.5 it is a self-hosted vLLM
  server (ADR-018, ADR-019), reached through the same OpenAI-compatible client. `JUDGE_BASE_URL` decides.

**Alternatives:**
- **DeepSeek** — rejected: no vision model on OpenRouter, so it cannot serve the judge role.
- **InternVL3, Pixtral, GLM-4.5V/4.6V, Llama 4 Maverick** — rejected: no structured-output support on OpenRouter as of 2026-07.
- **Llama 4 Scout** — works, but Meta's Community License is not OSI-approved. Available if needed; prefer Apache-2.0.
- **Self-hosted Gemma/Qwen** — rejected in ADR-015 (ops burden on a solo build; no GPU on Northflank).
- **Gemini** (the original decision) — precluded by ADR-015.
