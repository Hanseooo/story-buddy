§ 0 Executive Summary & System Architecture

The Research Problem & The Role of the Consistency Judge ADR-004 · ADR-018 · PREREGISTRATION_OBJ4

In automated digital picture book generation for children, character identity drift across sequential scene illustrations is the critical failure mode. StoryBuddy employs a closed-loop control architecture where a Vision-Language Model (VLM) Judge evaluates character instance consistency between a generated scene and a canonical reference image. If inconsistent, the pipeline triggers a targeted regeneration loop.

Objective 4 evaluates whether fine-tuning an open-weight 7B parameter VLM (Qwen2.5-VL-7B-Instruct) using QLoRA can match or exceed the performance of a zero-shot 27B model (gemma-3-27b-it) on human pairwise consistency judgments of stylized, non-human, and child-authored characters, while reducing latency and operating at zero marginal inference cost.

§ 3 Nine-Phase Operational Blueprint

Phase 1: Governance, Consent, Sanitized Intake & Style Allocation PHASE 1

Donated stories originate from child authors (Grade 5–6). Strict ethical guidelines govern intake before any text is parsed or rendered.

1.1 Ethics & Redaction Seam

  • Consent/Assent: Affirmative guardian consent and child assent recorded outside repository.
  • Random Receipt Ledger: Contact & identity mapping stored in an encrypted offline store. Never in repository, DB, or logs.
  • Two-Person PII Redaction: Manual PII redaction followed by an independent reviewer confirmation. Presidio Filipino recognizers provide backend backstop.

1.2 Frozen Style Allocation (ADR-042 Amendment)

  • Synthetic (30): 24 Train (8 Cel, 8 Gouache, 8 Cut-Paper) + 6 Val (2 Cel, 2 Gouache, 2 Cut-Paper).
  • Donated (15): 10 Primary (4 Gouache, 3 Cel, 3 Cut-Paper) + 5 Backup (1 Gouache, 2 Cel, 2 Cut-Paper).
  • Fail-Closed Replacement: If a primary donor withdraws, replacement MUST be an unused backup of the exact same art style. Otherwise freeze fails closed.
Phase 2: Corpus Generation & Asset Encoding PHASE 2

The canonical Phase-1 LangGraph state machine generates all story bundles. finetune.build_corpus is the sole fal.ai caller.

Handling Pipeline Regenerations & Rejected Images

During production graph execution, when consistency_check flags an inconsistent scene, the node triggers regenerate (ADR-010). Crucial Fact: The rejected (inconsistent) intermediate images are tracked in StoryMemory.cost and run provenance, but they are NOT uploaded to the annotation queue or stored in the dataset freeze. Only the finalized scenes (and their canonical references) form the natural positive pairs.

2.1 Asset Format Invariants (ADR-027)

  • Canonical References: Stored as uncompressed PNG to preserve reference fidelity.
  • Scenes: Transcoded once to WebP (Quality ≈ 82). Re-encoding is forbidden.
  • Integrity: Decoded width, height, MIME magic bytes, and SHA-256 hashes recorded in AssetRecord.

Phase 3: Hard Negative Synthesis & Queue Materialization PHASE 3

A balanced training dataset requires negative pairs (inconsistent characters). Natural generation yields ~85% positive pairs. To create high-quality negatives without paying for additional image generation, StoryBuddy constructs cross-character hard negatives.

Pair Type Allowed Split How It Is Formed Annotation Requirement
Natural Pipeline Pairs Train, Val, Test Canonical Reference $C_i$ paired with Scene $S_i$ from the same story. Mostly positive (consistent). Dual independent human annotation + adjudication on disagreement.
Constructed Hard Negatives Train Only (Strictly forbidden in Val & Test) Canonical Reference $C_a$ paired with Scene $S_b$ of a visually similar target character $C_b$ (same species & style). Pre-frozen in dataset_selection.json. Automatic ground truth: same_character = False.

Candidate Hard Negative Inspection & Freeze Process

  1. Run candidate report: uv run python -m finetune.build_dataset --candidate-report --data ../data/judge/corpus
  2. Researcher visually inspects reference pairs across 5 dimensions: body shape/silhouette, key colors, facial features, clothing/accessories, and art style.
  3. Record the closest matching target in data/judge/intake/dataset_selection.json and lock hard_negatives_frozen_at timestamp.
  4. Materialize pairs to Supabase:
    uv run python -m finetune.materialize_pairs --data ../data/judge/corpus --donated-intake ../data/judge/intake/donated.json --selection ../data/judge/intake/dataset_selection.json
Phase 4: Human Visual Annotation & Adjudication Protocol PHASE 4

Human annotation establishes the gold ground-truth reference labels. The annotation interface runs at (research)/annotate/ in the frontend.

4.1 Annotation Protocol & Blinding

  • Blinded Presentation: Annotators see short-lived signed URLs, randomized presentation order, and opaque filenames. No provenance or split exposed.
  • Dual Labeling: Exactly two independent ordinary annotators label every natural pair.
  • Adjudication: If Annotator 1 and Annotator 2 disagree on same_character, a designated third researcher (Adjudicator) reviews and casts the binding tie-breaker.
  • Inter-Rater Agreement: Cohen's $\kappa$ computed post-labeling; drift checks evaluated midway.

4.2 Frozen Visual Rubric & Gating Taxonomy

  • same_character (Bool): Radio [Different / Same]. Primary label.
  • anatomy_intact (Bool): Checkbox for missing/extra limbs or body distortion.
  • text_free (Bool): Checkbox confirming no unwanted lettering or text.
  • failure_reasons (7 closed checkboxes):
    wrong_color, missing_core_attribute, wrong_species, clothing_drift, face_hair_drift, wrong_style, unwanted_artifacts.
⚠️ Label Polarity Conversion (Stated Once to Prevent Inversion)

In the database table annotations, same_character = True means the character is consistent. In the capstone manuscript and evaluation metrics, the positive class is Class 1 = Different Character (Inconsistent).
The conversion label = not same_character is applied strictly in build_dataset.py and nowhere else.

Phase 7: Validation Checkpoint Selection & Evaluation Locking PHASE 7

To prevent test set contamination, checkpoint selection and control baseline threshold tuning occur exclusively on the validation split (val.json).

  1. Inventory Checkpoints: uv run python -m finetune.evaluate validation-inventory --runs ../data/judge/runs/obj4-v1 --out ../data/judge/evaluations/obj4-v1/validation_candidates.json
  2. Launch vLLM Server: Start local vLLM instance serving the Qwen base + candidate LoRA adapters.
  3. Capture Validation Predictions: uv run python -m finetune.evaluate capture-validation --freeze ../data/judge/freezes/obj4-v1 --candidates ../data/judge/evaluations/obj4-v1/validation_candidates.json --predictions ../data/judge/evaluations/obj4-v1/validation
  4. Select Best Checkpoint per Seed & Fit Cosine Baselines: Checkpoint is selected by maximizing F1 on the minority class (different_character). Thresholds for CLIP and DINOv2 controls are fitted on validation.

8.1 Statistical Protocol (PREREGISTRATION_OBJ4 §5)

  • Clustered Bootstrap CI: 10,000 resamples clustered by char_id (resampling whole characters, not individual pairs, to account for intra-character error correlation).
  • Significance Testing: McNemar's exact test on paired decisions.
  • Metrics: Precision, Recall, F1 (primary), AUROC, Cohen's $\kappa$ vs humans, Brier score calibration.
  • Transfer Benchmark: DreamBench++ evaluation (150 subjects, binarized at $\ge 3.0$ human rating).

8.2 Cold-Start vs Warm-Start Latency

  • The very first inference call per judge is isolated as the cold-start observation.
  • Warm-start latency reports mean ± sample SD excluding the cold start.
  • Dollars per call benchmarked against OpenRouter live rates at measurement date.

🔬 The Pre-Registered Rung-D Defect Exception (Read-Once Guard)

If Rung D lands, it signifies an engineering bug (e.g. tokenizer mismatch, broken image normalization, corrupted target JSON). The Pre-Registered Protocol permits exactly ONE (1) second held-out evaluation, strictly after:
1. The defect is investigated and fixed exclusively on train and validation data.
2. The operator submits --deviation <PATH> documenting the bug commit, validation evidence, and adviser sign-off.
3. Both evaluation readings and the defect description are reported in full in the manuscript. A third read is unconditionally forbidden.

§ 5 Binding Invariants & Pre-Registered Decision Rules

Non-Negotiable Research Invariants

  • Character-Disjoint Splits (ADR-018): All images of a character lineage belong to exactly ONE split (Train, Val, or Test). Splitting by pair is strictly forbidden.
  • Test Set Purity: Held-out test split consists 100% of donated child stories. Zero synthetic stories and zero constructed negatives may enter test.
  • Constructed Negatives Train-Only: Hard negatives matching species & style are restricted exclusively to the training split.
  • Open-Weight Models Only (ADR-015): All pipeline and fine-tune models are open-weight (Qwen, Gemma, Mistral). No closed API models.
  • Judge is a Control Signal, Not an Outcome: The fine-tuned judge acts inside the pipeline control loop; it is never used to score Objective 3 expert validation.

Data & Safety Protections

  • Fine-Tuned Judge Never On Safety Path: Safety moderation runs on prompted Gemma with its own rubric. Consistency has best-of retry; safety has none.
  • PII Redaction (Presidio): Only already-redacted text is hashed or persisted. No student identity enters training prompts.
  • Fail-Closed Test Access: Access to manifest.test.jsonl is cryptographically locked and recorded in test_access.jsonl.
  • Malformed Output Handling: Any unparseable JSON emitted by a judge baseline is scored as an explicit miss on different_character charged to that model.
